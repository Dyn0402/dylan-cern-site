Preliminary analysis — the board

First full pass over the 2026 campaign · 7–13 September 2026 · preliminary throughout

This is the working board for the first end-to-end analysis of the campaign, not a result. It holds four things: where we stand, the plan as a pipeline, what is deliberately not being done this week, and a dated log of what was decided along the way. The run quality assurance it stands on is finished and lives on its own four pages — nothing here re-does it.

Everything on this page is preliminary and internal. A number here has not been through a second pair of eyes unless the log entry beside it says so.

Where we stand

  • 0 Stages complete of 8 in the pipeline
  • 1 In progress what is being worked on right now
  • 0 Blocked waiting on something outside the week
  • 0 Open questions unresolved, listed below

The one-line status. The campaign full pass is done — 12 929 condor jobs, all 293 sub-runs, 47.8 M reconstructed events, 9.5× the earlier allowlist pass — and the blocker has moved from statistics to calibration. The in-situ angle scale k is the only per-run number in the chain, and it does not transfer: the four calibrated runs cluster to ±2 % while run 145, whose scale every calibrated angle currently carries, sits 13–17 % high on chamber C and 7–14 % high on D. It is not a sampling artefact; that was tested and excluded. Chamber A is the only arm whose forward model fits its data and the only arm whose scale is stable, so a real per-detector recalibration is scheduled for October. Until then the pass is being pushed through with per-run k where it certifies, and the tracking distributions are being opened up run by run and tag by tag to find what drifts. The geometry remains in hand: the He-3 capsule is imaged at 9.3 mm off the beam axis, inside its own 10 mm bore, from a pointing crossing that needs no drift velocity.

The plan, stage by stage

Each stage names what it produces — a file, a number, a plot — because a stage with no artefact cannot be called done. Later stages depend on earlier ones, but the order is the intended one, not a hard chain: several can run in parallel once the sample is frozen.

  1. Freeze the analysis sample

    Decide, once and in writing, which runs and which sub-runs enter the preliminary analysis — and write the list to a file every later stage reads. Beam runs only, ³He target, production trigger, fully processed and joined to n_TOF. Everything downstream quotes this list rather than re-selecting.

    • Producessample.csv — run, sub-run, file tag, n_TOF run, and the reason each was kept or cut, plus the beam-time timeline figure
    • ReadsDREAM QA, the match, pedestals
    • Watch forthe HV-scan runs — 64 of them swept a voltage mid-run and are not a fixed operating point; and run_79, whose arm-A x view needs channels 448–511 masked

  2. Time base and the flash veto

    Put every trigger on the n_TOF time-of-flight axis and decide where each event window usably begins. The gamma flash saturates the front end and the wall takes a known time to recover, so the start of the window is a cut, not a constant — and it is the cut that most directly sets how much beam survives. Comes before the filter, because the filter writes the flash time into every row.

    • Producesa per-trigger time-since-flash and En, and one stated veto window with the number it costs
    • Readsthe flash charge measurement, the clock QA
    • Watch forthe PSS ringing — a coherent artefact in the hit sample, vetoed before anything is counted

  3. The candidate filter

    Reconstructing 31 M triggers × four chambers blind is of order 105 core-hours, which is not a week. So every trigger is first classified from combined_hits alone — noise bands removed, hits clustered, clusters typed, track-like clusters counted per chamber — and crossed with which n_TOF arms saw a wall+plastic coincidence. One terminal class per trigger, so the ledger is a partition and every later efficiency has an honest denominator.

    • Producescandidates.parquet, one row per DREAM trigger (~31 M) — the class, the per-chamber cluster counts, the n_TOF arm flags, the flash time
    • ClassesINTER two chambers · INTRA two tracks in one · IMPLIED one chamber but two n_TOF arms · SINGLE · BUSY pile-up · NONE
    • Watch forthe filter's own efficiency is unmeasured going in — the prescaled control sample in the next stage is the only thing that measures it

  4. Reconstruct the candidates (WFT)

    The frozen waveform-first reconstruction, on condor, one job per (arm, file tag), with an event-id allowlist so only selected triggers are fitted. Everything in INTER, INTRA and IMPLIED — and for IMPLIED, the silent chamber too, forced — plus a prescaled control drawn from the rest. This is the expensive stage and the one that sets the week's pace.

    • Producesper-(arm, tag) track tables and the multi-track candidates sidecar, plus a completion ledger and a measured cost per 1,000 events
    • Needsthe sample frozen and the filter run; the calibration bundle pinned per chamber and per run condition, recorded in every row
    • Watch fordouble tracks closer than 12 mm fit as one bad-χ² compromise — they are flagged and counted, not recovered

  5. The track database

    X/Y pairing into 3D segments, into the global frame, with the crossed scintillator volumes predicted per track — and the n_TOF hits of the same event attached beside them. This is the artefact the week has to leave behind, because every later analysis reads it instead of re-running anything.

    • Producestracks.parquet (one row per 3D segment: geometry, quality, charge, timing, pointing, predictions, calibration provenance) and scint.parquet (one row per n_TOF hit, with the track predicted to have crossed it)
    • Rulenever collapse an ambiguity at write time — a two-track event's X↔Y pairing is genuinely ambiguous, so both hypotheses are written with their scores
    • Watch fora bundle used outside its conditions is a silent error; the row has to be able to say which bundle it is

  6. Scintillator positions

    Where a particle crossed the n_TOF scintillators. Across the wall: the segment that fired, four segments of 100 mm. Along the bar — the beam direction, since EAR2's beam is vertical — two independent estimators, the top–bottom transit time and the logarithm of the amplitude ratio. Both were characterised on n_TOF data alone; what is new is calibrating them against Micromegas tracks, which supply the truth the earlier study did not have.

    • Producesa fitted attenuation length and Δt scale per bar, a quoted position resolution, and the position column in scint.parquet
    • Needsthe track database, for the impact points
    • Watch for√(Atop·Abot) varies +9.1 % across a bar, and whether that is light collection or a reconstruction bias has never been separated

  7. Pair finding — intra, inter and implied

    From tracks to candidate pairs, in three topologies kept apart on purpose. Intra-chamber: two segments in one chamber, θ below ~90° — the continuum control. Inter-chamber: one segment in each of two chambers — the signal region, because an X17 opening angle of 109° or more cannot fit inside one chamber. Implied: one good track plus an n_TOF coincidence in a second arm that produced no track, which is how a chamber-B or chamber-D miss is recovered. Every cut gets a line in a cutflow table.

    • Producespairs.parquet and a cutflow per topology, quoted in every later plot
    • Needsthe database; and for the implied topology, a measured false-positive rate from the accidental two-arm rate and from a blinded control
    • Watch forthe four arms are not equivalent — B and D are tagging chambers this week, and any pair using their angle is reported separately from an A×C one

  8. The opening-angle spectrum

    The headline distribution, uncorrected: opening angle per candidate pair, one spectrum per topology. Plotted first with no acceptance correction and no background subtraction, so that what the correction and the subtraction each do is visible rather than assumed. No invariant mass — that needs an energy calibration we do not have.

    • Producesthe raw opening-angle spectra with their statistical errors, and the numbers behind them as CSV
    • Needspair finding
    • Watch forbinning chosen once and stated, not tuned after the fact

  9. Acceptance and efficiency

    A straight-line toy through the as-built active-volume model: pairs thrown from the capsule with a flat opening-angle distribution, folded with the per-chamber reconstruction efficiency measured on the control sample. Geometry only this week — no multiple scattering. The active area is measured, not assumed.

    • Producesa correction curve versus opening angle, per topology, with the geometry it assumes stated
    • Readsthe measured active area
    • Watch forthe trigger efficiency is a separate factor from the geometric one; keep them separable

  10. Backgrounds

    What else makes two tracks that look like a pair. The accidental rate from event mixing across bunches; the cosmic rate straight off the beam-off runs taken at the production operating point; the flash-induced residual from the veto sideband. All data-driven, and the accidental estimate comes first because it needs nothing from simulation.

    • Producesone background shape per component, normalised, and their sum against the raw spectrum
    • Needspair finding for the shape; the time base for the off-time window
    • Watch fora background normalised to the same data it is subtracted from will always fit

  11. The preliminary picture

    Corrected spectra, background subtracted, with the IPC expectation overlaid — and an honest statement of what the sample can and cannot say. If the answer this week is “the statistics do not reach the question”, that is the result and it gets written down as one.

    • Producesthe summary figures, sized for a projected slide, and a note published beside this board
    • Needsthe spectrum, the acceptance and the backgrounds
    • Watch forno systematic uncertainty is being claimed this week — say so on the plot

Not this week

Deliberately out of scope for the preliminary pass. Each item says why it is deferred and what would unblock it, so that nothing here can be mistaken for an oversight.

  • Systematic uncertaintiesdeferred Why: a preliminary spectrum with a full systematic budget takes longer than a week, and a half-done budget is worse than a stated absence. Unblocked by: the statistical picture settling first — the budget should be built against a spectrum that is not going to move.
  • Per-channel gain calibrationdeferred Why: the preliminary pass uses one gain per chamber. Per-channel gain changes resolution, not the presence or absence of a peak. Unblocked by: the pedestal and threshold work already on the QA page, plus a pass over the pulser runs.
  • The HV-scan runsdeferred Why: 64 runs swept a voltage mid-run, so they have no single operating point and cannot enter a sample that assumes one. Unblocked by: splitting them at the setpoint boundaries — worth doing, and worth roughly a quarter of the campaign’s runs.
  • Cosmic-bench cross-calibrationdeferred Why: the June fleet characterisation is finished and published, but folding its per-detector resolution into the n_TOF chambers is its own study. Unblocked by: nothing external — it is a time cost, not a dependency.
  • Merged-cluster double tracks (D1)deferred Why: two tracks closer than 12 mm fit as one bad-chi2 compromise, but they are flagged quality_ok=False and counted, so the loss is measured rather than silent Unblocked by: a two-column NNLS design matrix in wft/model.py plus a 1-vs-2-track model-selection penalty
  • Simulating the double-track finding efficiency (D2)deferred Why: we can say we lose some merged pairs, not how many. It does not block a preliminary spectrum, it blocks calling one a measurement Unblocked by: Geant4 pairs pushed through the response sim and the full chain, binned by opening angle and track separation. The most valuable single item on this list
  • Breaking the X-Y pairing ambiguity for simultaneous tracks (D3)deferred Why: for a two-track event, which x goes with which y is genuinely degenerate; this week writes both hypotheses and quotes the spread as a systematic Unblocked by: two handles already in the schema and unused: whether the pairing points back at the He-3 sample, and whether the two projections carry the same charge profile
  • Calibrating chambers B and D (D4)deferred Why: their in-situ angle scale is unphysical (k = 1.99 and 1.70, drift velocities down to 21 um/ns against a 42.6 prior), and B truncates 46-56 percent of its columns. They enter as tagging chambers only Unblocked by: a dedicated per-chamber study. This is the biggest single limit on the signal region, since the X17 topology needs one of them in most events
  • In-situ drift velocity and diffusion (D9)deferred Why: the chain still runs on values transferred from the June bench, which is the largest unvalidated assumption in it. A wrong v scales angles, it does not invent a peak Unblocked by: porting the stacked-NNLS erfc-endpoint gap study to the beam runs; it costs no refit
  • dE/dx in the Micromegas (D5)deferred Why: gain variation across a chamber is expected to dominate, so a dE/dx number now would measure the gain map rather than the ionisation Unblocked by: a per-region gain map from the pulser and source runs
  • Scintillator energy calibration and calorimetry (D6)deferred Why: this is what would unlock the invariant mass, and it is a project rather than a task. Without it the deliverable is the opening angle alone Unblocked by: an energy scale for the plastics, the SiPM wall and the liquids, each verified before use
  • Liquid scintillator gain across the surface (D7)deferred Why: no liquid amplitude is used as energy this week, so the gain map does not bite yet Unblocked by: measuring how far the gain moves with distance from the PMT and across the surface, with Micromegas tracks defining the impact point
  • The neutron-energy axis (D11)deferred Why: time-since-flash is already written into every row, so nothing is lost by not analysing it this week Unblocked by: the opening-angle spectrum resolved in E_n, once there are enough pairs to bin twice
  • Absolute alignment (D8)deferred Why: arms A and C agree on a source 9 mm off axis, and whether that is a real target offset or a survey error cannot be separated by more tracks. Positions are quoted to about 1 cm and that is enough for an angle Unblocked by: survey information, or an independent beam-spot measurement
  • Beam-side kernel calibration (a ref-free training selector)deferred Why: wft.calibrate is ref-pinned to the M3 telescope, which the beam does not have, so this is new development rather than a re-run -- and only chamber B currently needs it Unblocked by: a training selector that pins on the target constraint tan = (u - foot)/d_perp instead of on a reference ray
  • Seeding on the hot-channel wildcarddeferred Why: measured on run_145 and it buys nothing: the rewritten clean-strip rule ties the old count-after-clustering rule on every fit metric, and wherever either relocates a seed the fit gets worse (chi2/dof 13.1 -> 20.6). The downstream cut gets the calibration benefit with no re-reconstruction, so there is no reason to spend a condor pass on this now Unblocked by: a candidate-ranking study rather than another constant. The seeder ranks clusters by strip count and both rules only change what gets counted; ranking by the fit's own _candidate_score, which is already computed and already offered 5 candidates per plane, would sidestep the ranking question entirely
  • Whether D's 'mostly-hot' triggers should be cut toodeferred Why: they are another 22 % of D and they still contain real tracks -- fitted p0 spread across the whole plane, IQR 308 mm, against 142 mm for the all-hot pile-up. Dropping them changes the angle scale by a rounding amount, so the sample is not worth it for the preliminary Unblocked by: a reason to care about D's angle resolution beyond the preliminary spectrum
  • Whether the all-hot triggers hide any real tracksdeferred Why: every piece of evidence says the CLUSTER is noise -- 35x local occupancy, connector-aligned, p0 piled on the band, chi2/dof 1.27 -- so cutting them is right for the angle scale. But a real particle could have crossed D in the same window and been lost inside one, which would make this a 29 % efficiency hole in D rather than a clean cut Unblocked by: the scintillator tag: ask whether all-hot triggers carry a wall+plastic coincidence at the rate real tracks do
  • A per-detector recalibration of the wft bundles for the n_TOF campaigndeferred Why: the bench-cosmic bundles reconstruct well enough to push the first full-pass campaign through, and arm A demonstrates the method is sound where the model fits Unblocked by: the October calibration effort - a dedicated pass on chambers B, C and D, starting with arm C's bundle, which is a different generation from the other three (diffusion parameters ~10x smaller, sharing ratio 0.82 against 0.60)
  • A browsable run-by-run and tag-by-tag QA pagedeferred Why: the campaign-wide QA pages answer one question each across all runs, which is what the analysis needs right now; picking one run or one tag and reading its own distributions is a presentation job, not an analysis one Unblocked by: the per-run efficiency work that unblocks the acceptance -- tracking_qa.py already writes per_run.csv and per_tag.csv over ~3,150 tags, so the data is there and only the page is missing

Open questions

Things that have to be decided before a later stage can be called done. A question that gets answered stays here with its answer attached.

  • Does the preliminary sample take the whole campaign, or only the runs after the 23 July pedestal step? The noise floor doubled on that date, and mixing the two epochs mixes two thresholds.

    opened 2026-09-07

    Resolved 2026-09-07: Only the production period: run_79 onward. run_67 is the quiet pre-23-July noise configuration and run_68 sits inside the pedestal bracket unplaced, so neither can be pooled with the rest. run_79 itself is kept but flagged - its arm-A x view needs channels 448-511 masked.

  • Is the flash veto one window for the whole campaign, or per chamber? Chamber A behaved differently through the pedestal history, and a single window would be set by the worst arm.

    opened 2026-09-07

  • What is the minimum sample size that makes the opening-angle spectrum worth plotting at all? Worth deciding before the reconstruction runs, not after.

    opened 2026-09-07

  • Can chambers B and D be rescued for the preliminary, or do they stay tagging-only? An X17 opening angle is at least 109 degrees and one chamber subtends about 40, so the signal topology needs one of them in most events - which makes their uncalibrated angle scale the binding constraint on the whole measurement.

    opened 2026-09-07

    Resolved 2026-09-07: Partly. D is rescued: on an interquartile charge window its three angle-scale estimators agree to 11% and reproduce to 3%, k = 1.751 (v 24.3 um/ns), so D now carries angles like A and C. B is not: its focus objective never turns over across the whole scan grid and its k jumps 1.35 to 2.30 depending on the charge window, so B stays tagging-only. B can still serve as a TRIGGER control in the pair analysis, since the trigger arm comes from the n_TOF slim rather than from the reconstruction.

  • Are implied pairs - one real track plus an n_TOF coincidence in a chamber that saw nothing - good enough to appear on the same plot as measured pairs, or only in a figure of their own? Turns on the false-positive rate, which is measurable from the accidental two-arm rate and from a blinded control.

    opened 2026-09-07

  • Does run_79 get masked, reweighted, or quoted separately in the campaign census? Its chamber-A x plane is 2.5x noisier than the rest of the campaign and it inflates INTER, INTRA and BUSY together. It is 16 of 293 sub-runs.

    opened 2026-09-08

  • Chamber D reads the scintillator wall backwards -- is it D's two wall ends swapped in the readout map, or D's Micromegas y strip plane mirrored? Both estimators flip together, so it is one flip somewhere in D's chain, and the data cannot say which link. D's own wall self-check is the strongest of the four (r = -0.83), and its shallow slope is what noise in the predictor does, both pointing at the Micromegas side; run_config declares the same FEU orientation for all four chambers, so an MM-side mirror would have to be an undeclared cabling difference. What would settle it is an external fact: the wall cabling map, or the y-plane strip mapping order, for arm D.

    opened 2026-09-08

  • How do we normalise the accidental pair background? The mixed sample gives the shape but no rate, and the Poisson product over-predicts by 2-4x because the trigger correlates the arms. The two-chamber rate solved the same problem with a control chamber -- does that transfer to a differential spectrum, or does it need an unbiased trigger sample?

    opened 2026-09-08

    Resolved 2026-09-08: Not a control chamber -- direct scintillator timing on the real inter-chamber pairs. arm1-arm2 tag time, unbinned two-component fit against is_control: f = 29 % [17,40] overall, 42 % [26,58] opposing (A-C), 16 % [0,32] perpendicular. Folding it into the spectrum itself is the next step -- f is measured only on the 16 % of pairs with a two-arm scintillator tag.

  • The capsule looks +22 mm high in y and ~9 mm off in X, and all chambers agree on both. Is that the target really sitting there, or a shared convention error in the strip-map origin? Three physically independent detectors sharing an offset argues for a convention; nothing in the tracks separates them. Needs survey information or a beam-spot measurement.

    opened 2026-09-08

  • Chamber D has 10.8 % of its cells running above 5x the plane median, five times the other chambers, and they are the only thing that moves D's angle scale. What are they -- a noisy connector, a gain non-uniformity, or discharge activity? Masking them improves D's calibration on every metric, so the practical answer for the preliminary is to mask; the physical answer is unknown and would decide whether D can be recovered rather than patched.

    opened 2026-09-08

    Resolved 2026-09-08: Characterised 2026-09-08: not discharges (median charge 0.94x normal, same as arm A) but wide, dilute, low-density clusters -- 2.2x more low-charge deposits over 1.7x more strips. Structurally they are whole x columns spanning the full plane height, i.e. bad CHANNELS not bad regions, and they sit on the 49.8 mm connector boundaries where D's dead runs also are. So hot and dead are one fault class and the cause is upstream of the gas. The remaining question is the physical one -- connector, grounding or cabling -- and the analysis plan is in HANDOFF_D_NOISY_CHANNELS.md: a per-channel classifier feeding reconstruction wildcards (never seed, keep down-weighted, cap influence) rather than a mask.

  • Chamber A's y view has a hot connector-8 run of its own -- channels 448-460, 21.7 % of the plane's hits, the same fault class as D's. Found 2026-09-08 while validating the classifier and not chased. The production cut is on x only so A is untouched either way, but anything that uses A's y angles should know A-y is not clean. Does A-y need the same treatment, or is A's y only ever used for position?

    opened 2026-09-08

  • Does the Al-capture pair background have to be simulated before the opening-angle comparison means anything? The first-look estimate says the capsule outproduces the gas in wide-angle pairs by 400-4000x, and with no magnet there is no energy cut to separate 7.7 MeV pairs from 20.6 MeV ones. Either it gets a Geant pass with an Al-capture generator and goes on the page as a second component, or the IPC curve there is being compared against the smaller of the two things present.

    opened 2026-09-09

  • Do we ask Viviani, Marcucci, Kievsky and Schiavilla for the 3He(n,e+e-)4He cross section at thermal? They already have the C0000 (1S0) and M1 (3S1) reduced matrix elements in the code behind PRC 105 014001 and simply stopped at En = 0.17 MeV. A run below 10 eV would replace our single-level E0 estimate, and the 2.1e-3 IPC/capture the rate table and the INTC proposal both use, with an ab initio number.

    opened 2026-09-09

  • Is the run-to-run spread in the angle scale k a real drift-velocity change, or the forward model absorbing something it does not describe? Chamber A, the only arm that fits well (median chi2/dof 6.0), is also the only arm whose k is stable to a few percent; C and D fit at 17 and 39-55 and scatter by 13-17 %. The per-run HV monitor logs are the one physical variable not yet checked - only run_145's is mirrored locally.

    opened 2026-09-10

  • 2026-09-11

    The neutron window is 2 eV to 0.35 meV, not 2.4 MeV, and that correction matters. neutron_energy.py had inferred the reach by taking the slim hits' tof floor of 1.00408e6 ns to be the gamma flash. It is not: the offset between tof and the flash is tflash, a per-detector-tree cable delay, measured directly now as tof - (t_pred_ns + dt_ns) and landing at 11.60-11.65 us on all twelve trees with a 5-14 ns spread. That also closes the loop that the hits and the triggers sit on one flash reference. The N93B gate opens 0.9349-0.9934 ms after the flash depending on the run and the acquisition closes at 75.5 ms, so the campaign spans 2.27 eV down to 0.35 meV with the track median at 31 meV, the thermal peak. This is what CLAUDE.md said independently and what the E0/M1 argument in ipc_born.py rests on: there is no resonance region in this dataset and no cut can make one. The 1 ms flash veto is in hardware, so a software veto is a cut on top of a gate, and its cost is now measurable per chamber for the first time. the track QA page, where the two columns are now plottable
