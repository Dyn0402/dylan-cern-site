How this notes section works

2026-08-07 · meta

A note is a file in pages/notes/. Everything else — the listing, the offline cache, the noindex tag — is generated from it.

Adding a note

Two shapes work, and the second is the reason this exists.

  • A fragment with front matter, like this page — it gets the site chrome, the nav, the theme toggle and style.css.
  • A complete standalone document, styling and all, dropped in untouched. The build injects only a noindex tag, the manifest link and the service-worker registration, and leaves the rest of the markup exactly as written.

Then python3 scripts/build.py and ./scripts/deploy-eos.sh. The listing at /notes/ is rebuilt from whatever is actually in the directory, so it cannot drift.

Dates

Sorting is newest first, on the date: field. A note without one sorts last and shows no date rather than being given a guessed one — deriving it from the file mtime would produce a different notes/index.html on every fresh clone and make build.py --check fail for no reason.

Offline

sw.js precaches the site and serves it from the cache first, refreshing in the background. Install the site to your home screen and the notes open with no network at all.

The cache name carries a hash of the precached files' contents, so a new note invalidates the old cache by itself — there is no version constant to remember to bump.

What the worker deliberately does not touch

A service worker at the root controls the whole origin, and this one shares its origin with /x17/ — the live DAQ dashboard, regenerated by the stats job at the beamline and owned by nothing in this repository. js/live-status.js fetches /x17/data.json with cache: 'no-store' precisely because run status must be fresh.

So the fetch handler is an allowlist, the same discipline as PAYLOAD in the deploy script: it calls respondWith() only for paths in the generated precache list and returns without touching anything else, which leaves the browser's normal networking in place for /x17/ and trigger_scheme.html. Widening it to a catch-all would start serving stale run status to anyone opening the dashboard.

Unlisted, not private

Every note carries noindex, nofollow and the listing is not in the site nav, so search engines skip it. That is obscurity, not access control — anyone with the URL can read it. This is deliberately not paired with a robots.txt Disallow: blocking the crawl would stop a crawler from ever reading the noindex, which is the tag that actually keeps a page out of an index.
